# v2.13.0 — Seni Bina Profil Detektif

Profil Detektif membungkus snapshot permainan sedia ada tanpa mengubah struktur KES 001–025, rekod, ganjaran, Lensa Bahasa, pencapaian atau Watak.

## Model data dan kunci

- `detektif-bahasa-profiles-v1` menyimpan registri maksimum lima profil: ID, nama, avatar dan masa kemas kini.
- `detektif-bahasa-profile-v1:<id>` menyimpan sampul `{ schemaVersion, profileId, revision, updatedAt, snapshot }`.
- `detektif-bahasa-active-profile-v1` berada dalam `sessionStorage`, maka dua tab boleh memilih profil berbeza.
- `detektif-bahasa-guest-v1` berada dalam `sessionStorage` dan tidak menggunakan slot kekal.
- `detektif-bahasa-v1` kekal sebagai sandaran legacy dan tidak dipadam.

Nama dinormalisasi, dihadkan kepada 16 aksara dan dimasukkan ke DOM dengan `textContent`. Enam avatar ialah Lensa, Nota, Kompas, Bintang, Idea dan Peta.

## Dasar tab dan penulisan

Setiap tab mengingati revisi terakhir yang dibaca. Penulisan hanya diterima jika revisi tahan lama masih sama. Perubahan dalam tab lain menyebabkan konflik dan menyekat penulisan basi; pengguna diminta memuat semula profil. Profil berlainan mempunyai sampul dan revisi berasingan.

## Pengurusan

Pemain boleh mencipta, memilih, menamakan semula, menukar avatar dan memadam profil selepas pengesahan. Ringkasan kad diperoleh daripada rekod dalam snapshot: kes selesai, bintang terbaik dan XP terbaik. Memadam profil aktif mengosongkan pemilihan tab dan kembali kepada pemilihan profil.

Eksport sandaran menghasilkan JSON dengan metadata profil dan snapshot penuh. Import sengaja ditangguhkan kerana ia memerlukan polisi pengesahan dan penggabungan yang berasingan.

## Kegagalan stor

Operasi penulisan dibungkus dengan pengendalian ralat dan bacaan semula. Data profil yang rosak tidak ditindih secara automatik. Ralat kuota atau penulisan dipaparkan tanpa memadam snapshot lain.
